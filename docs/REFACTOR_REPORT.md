# RunFlow 全栈重构报告

日期：2026-09-09。规范依据：OpenSpec 变更 `refactor-runflow-fullstack`，以及 [PRODUCT.md](../PRODUCT.md) 和 [DESIGN.md](../DESIGN.md)。

本次重构以开始工作时已存在的 RunFlow v2 未提交内容为基线，修复编辑丢失、保存状态失真、文件失败处理和键盘操作问题。原工作目录保留，修改在隔离工作树内完成。

**工程验证已通过。** 2026-09-09 的最终 `pnpm check` 完成前后端类型检查、33 个测试文件 / 170 项测试和全部构建，退出码为 0。提交、推送和归档另按实际交付记录确认。

## 1. 目标与范围

保留现有 DSH 原生工作流能力、Remote 契约、v2 文件格式和图编辑功能，在现有边界上提取草稿持久化协调器、浏览器存储访问、对话框焦点管理、原子 JSON 写入和持久化结构校验。

本次没有增加新的触发器能力、替换 Host、引入云服务或数据库，也没有进行生产数据迁移或实际部署。验证使用本地预览、受控模拟对象和临时文件，不通过真实 Agent、网络或 shell 工作流验证执行效果。

## 2. 系统、数据与威胁模型

### 系统边界

| 边界 | 职责与权威来源 |
| --- | --- |
| React 18、React Flow、Zustand 编辑器 | 显示图、参数与执行证据，保存当前草稿；通过版本化 gateway 调用 Host |
| DSH 主会话与 Remote | 继续使用现有主 Agent 授权边界；前端状态不替代 Host 授权 |
| Cordis Host 服务 | 校验与执行工作流、管理 Provider 快照、处理取消、节点源码和执行记录 |

| 浏览器存储 | 已连接 Host 时保存可选缓存和偏好；离线编辑或本地模板的显式保存失败必须向用户反馈 |

### 故障与威胁模型

本轮重点是并发顺序和故障造成的数据完整性问题：慢响应、乱序确认、会话切换、撤销后再次保存、保存与删除重叠、磁盘写入或替换失败、watcher 重载竞争、浏览器存储拒绝访问或配额不足，以及格式错误的持久化文件。

隐私审查覆盖拟提交 Markdown 和已有待提交截图。依赖审计检查已知公告，不能据此证明产品代码不存在安全缺陷。本次没有重新设计身份认证，也没有验证恶意第三方 Provider 的隔离能力。

## 3. 必须保持的不变量

1. 最新编辑在切换标签、延迟保存和失败保存后仍可恢复；失败不能被标成“已保存”。
2. 同一队列仍有后续操作时，较早的确认不能清除草稿，即使其内容恰好与当前撤销后的内容相同。
3. 删除在先前保存之后执行；删除期间的新保存不能重新创建目标。失败保留可恢复状态，旧会话响应不修改新会话状态。
4. 浏览器缓存或偏好失败不打断编辑和 Host 保存；离线保存、离线删除和模板保存失败必须如实反馈。
5. 启动前已经取消的请求不得进入节点执行器。
6. 修改源码后，旧测试的成功结果不能认证新 revision；并发提交或删除不能吞掉后来创建的草稿。
7. 替换失败保留旧文件与旧的有效内存状态；watcher 重载相同持久化快照不能使提交或删除的状态判断失效。
8. 无效 Workflow、Execution 和嵌套字段不能破坏健康记录的读取；原始无效文件保留。
9. 对话框拥有可访问名称和内部焦点，Tab 循环、未被消费的 Escape 关闭、关闭后恢复存活触发点；录制快捷键先消费 Escape。
10. 文档不含具体主机路径、个人信息或可识别凭据；隐私检查失败信息只显示位置和类型。

### UI 方向

本轮重点改善键盘焦点、保存与错误反馈、隐藏内容的无效工作，以及窄屏中的控件可理解性。错误和执行状态应有文本或图标，不能仅靠颜色表达。命令面板和模板是上下文工具；已有类型端口、多输出、分组、重路由、子流程、模板和源码编辑能力继续保留。

模板保存先尝试持久化，再更新列表和清空名称。失败保留现有列表与输入，并显示可访问的错误提示。真实浏览器已检查 375、768、1024、1440 CSS 像素：页面无横向溢出，画布可用宽度依次为 327、704、960、1188 像素。

原基线有 26 个测试文件，其中 18 个 TS 文件、8 个 TSX 文件；共有 92 项测试，91 项通过，热加载 Provider 测试触发 5 秒超时，并出现后续目录清理失败。Vitest 没有默认排除前端 TSX，之后文件数增长来自本轮新增回归测试。

独立审查发现并推动修复了两类 P2 问题：

- **watcher 与提交/删除竞争：** 同内容磁盘重载重建对象身份，造成提交返回持久化成功、内存和重启后却仍是草稿，或删除后内存仍保留记录。修复让相同 revision、来源和持久化元数据的快照复用既有记录，真实变更继续替换；补充确定性交错回归。
- **撤销与保存队列竞争：** 保存 A、排队保存 B、本地撤回 A 时，旧确认可能提前清除 dirty 和草稿；导航后会丢失 A。修复让非队尾操作的确认保留草稿，并覆盖撤销最终保存失败和删除队列组合情形。

独立审查也复核了最后的保存提示、减少动画与 Inspector 布局增量，未留下未解决的实证 P1/P2。审查不等于生产发布认证。
